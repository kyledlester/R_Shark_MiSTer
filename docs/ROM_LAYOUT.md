# ROM layout

Reference: MAME 0.289 `ROM_START( rshark )`. Tool: `scripts/romtool.py` (never writes ROM data into
the repository; outputs go to `local/`).

## MAME regions (verified byte-exact against MAME's own region memory, `dump_regions.lua`)

| Region | Size | Contents |
| --- | --- | --- |
| maincpu | 0x40000 | ROM_LOAD16_BYTE rspl00 @0 (even = high byte), rspu00 @1 |
| audiocpu | 0x10000 | rse3 |
| sprite | 0x200000 (16BE) | rse4 @0 / rse5 @1, rse6 @0x100000 / rse7 @0x100001 |
| fg1 | 0x100000 (16BE) | rse11 @0 / rse10 @1 |
| fg0 | 0x100000 (16BE) | rse15 / rse14 |
| bg1 | 0x100000 (16BE) | rse17 / rse16 |
| bg0 | 0x100000 (16BE) | rse21 / rse20 |
| tmap_hi | 0x80000 | rse12 @0, rse13 @0x20000, rse18 @0x40000, rse19 @0x60000 |
| oki | 0x40000 | rse1 @0, rse2 @0x20000 |

Each bg/fg region holds **both** the tilemap and the tile graphics: words 0x00000-0x1FFFF (bytes
0x00000-0x3FFFF) are the tilemap ("tilemap infos"), and the whole region is also decoded as 8192
16x16x4 tiles (so tile codes 0-2047 alias the map data). `tmap_hi` holds one colour byte per
tilemap entry (low nibble used) for each layer: fg1 @0, fg0 @0x20000, bg1 @0x40000, bg0 @0x60000.

## Super-X (`superx.zip`, MAME `ROM_START( superx )`)

Same regions and sizes. maincpu is ROM_LOAD16_BYTE (2.3m even, 3.3l odd); audiocpu 1.5u; sprite
spxo-m05.10m and fg1/fg0/bg1/bg0 spxb-m04.8f / m03.8j / m02.8a / m01.8c are **ROM_LOAD16_WORD_SWAP**
single files (region even byte = file byte 2k+1); tmap_hi spxb-ms3 / ms4 / ms2 / ms1 (fg1, fg0, bg1,
bg0 order, as R-Shark); oki 4.7v + 5.7u. `romtool.py regions --game superx` is byte-identical to
MAME's own region memory for all nine regions (`dump_regions.lua`), including the word-swapped ones.

Because the stream carries MAME odd bytes at even stream offsets, a word-swapped file's own byte
order *is* the stream order: the Super-X MRA sends those files as plain parts (and the first 0x40000
bytes again as the tilemap copies), with no interleave. `romtool.py mracheck --game superx`: PASS.

## Game select (ioctl index 1)

Each MRA sends one byte before the ROM stream: 00 = R-Shark, 01 = Super-X (address map select).

## MiSTer ROM stream (ioctl index 0, hps_io WIDE=1)

The MRA (`mra/R-Shark (set 1).mra`, generated by `romtool.py mra`) delivers:

| Stream | Length | Content |
| --- | --- | --- |
| 000000 | 200000 | sprite (word) |
| 200000 | 100000 | bg0 (word) |
| 300000 | 100000 | bg1 (word) |
| 400000 | 100000 | fg0 (word) |
| 500000 | 100000 | fg1 (word) |
| 600000 | 40000 | bg0 tilemap = bg0 region 0-3FFFF again (`offset=0 length=0x20000` parts) |
| 640000 | 40000 | bg1 tilemap |
| 680000 | 40000 | fg0 tilemap |
| 6C0000 | 40000 | fg1 tilemap |
| 700000 | 80000 | tmap_hi (byte) |
| 780000 | 40000 | oki (byte) |
| 7C0000 | 40000 | maincpu (word) |
| 800000 | 10000 | audiocpu (byte) |

Word regions: `map="10"` for the MAME even-offset ROM, `map="01"` for the odd one, so with WIDE=1
`ioctl_dout` is the big-endian 68000 word (convention confirmed from the owner's hardware-proven NA-1
MRAs against `mame -listxml`). Byte regions: `ioctl_dout[7:0]` = even byte.
`romtool.py mracheck` re-interprets the MRA XML independently and compares the stream with the
layout table: PASS (0x810000 bytes).

## FPGA placement

| Data | Where | Format |
| --- | --- | --- |
| maincpu | BRAM 128K x 16 | 68000 words |
| audiocpu | BRAM 64K x 8 | bytes |
| sprite / bg0 / bg1 / fg0 / fg1 graphics | SDRAM 0x000000-0x5FFFFF (stream address) | each 128-byte tile reordered so a 16-pixel row is 8 contiguous bytes (one 4-word burst) |
| bg0 / bg1 / fg0 / fg1 tilemap + colour | SDRAM 0x600000 / 680000 / 700000 / 780000 | 2 words per entry: {attr}, {00, colour}; entries ordered row-major (row * 4096 + column) |
| oki | SDRAM 0x800000 | byte pairs little-endian per word (byte address k -> word k/2, byte k&1) |

Tile reorder (both the sprite and the tilemap layouts store a 16-pixel row as 4 bytes at 4*r and 4
bytes at 64+4*r): MAME byte offset bits {h, r3..r0, b1, b0} (bits 6..0) -> SDRAM {r3..r0, h, b1, b0}.
Tilemap entry index (MAME `TILEMAP_SCAN_COLS`, 32 rows): i = column*32 + row -> row*4096 + column,
so the entries of one tile row are contiguous (a 4-word burst returns 2 columns with their colours).
`romtool.py images` writes the exact SDRAM image the loader produces (`local/sim/sdram_be.bin`) plus
`maincpu.hex` / `audiocpu.hex` for simulation.
